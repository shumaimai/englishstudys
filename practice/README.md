## 採点

`data/r8-listening/answers.json` に、正解・配点・
「全部正解の場合のみ点を与える」組を入れてある。

- どちらも全問正解で **100点** になることを確認済み
- **全部そろって初めて点になる組**
  - リスニング … 問18〜21（4点）／問28・29（2点）／問30・31（2点）
  - リーディング … 問9〜12（3点）／問26〜29（3点）
- **順序を問わない組**（どちらの順で選んでも正解）
  - リーディング … 問22・23（各2点）／問24・25（3点）／問33・34（4点）／問40〜42（4点）
- 一度答えたら選び直せない。その場で採点する形にしているため
- 大問や結果の升目から**選び直すと、その分の記録は消えて最初から**

選択肢の数は設問によって違う。

- 問22〜25、問28〜31 … **6つ**（①〜⑥）
- 問18〜21 … **5つ**（①〜⑤のうち4つを順に並べる）
- そのほか … 4つ（①〜④）

## 公開する前に必ず読むこと

**このデータは、まだ公開してはいけない。**

試験問題の著作権は大学入試センターにある。二次利用には
**利用前に「試験問題利用申請」が必要**で、いまは申請中。
許諾が下りるまで、音声も冊子の画像も外に出さない。

許諾が下りたら、リポジトリの `.gitignore` にある
`practice/data/` の行を消して、その上の3行の `#` を外す。
それまでは手元でだけ動く（公開されないだけで、動作は同じ）。

## 中身の作り方（作り直すとき）

音声の切れ目は、耳で決めたのではなく次の手順で出した。

1. 音声全体を文字起こしして、`Question number N`・`Listen again`・
   `これで第○問は終わりです` の位置を拾う
2. 無音の長さで区切りを確かめる。第1問Aなら設問の切れ目は6.8秒、
   第3問なら8.8秒と、規則的に分かれている
3. 切り出した25ブロックの**頭と末尾の両方を聞き直して**、
   狙った設問から始まり、途中で切れていないことを確かめる

3をやったおかげで2箇所の間違いが見つかった。

- 問18〜21 が途中で切れていた（文字起こしが案内を二重に出していた）
- 第6問B の頭がずれていた

音声には Xing ヘッダが無く、そのままでは頭出しがずれる。
`ffmpeg -c:a copy -write_xing 1` でヘッダだけ足してある。
**入れ替えるときは同じ処理をすること。**
