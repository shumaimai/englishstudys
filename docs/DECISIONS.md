# 設計の記録

このファイルは、作りながら決めたことと、その根拠を残すためのもの。
新しく作業を始めるとき（別の道具を使うとき、しばらく間が空いたとき）は、
まずここを読めば同じ前提から再開できる。

---

## 1. 何を作っているか

英語のリスニング学習を助けるウェブサイト。

出発点は、全商英語検定1級のリスニングで69点（合格まであと少し）だったこと。
点が取れなかったこと自体より、**何が聞き取れていなかったのかが分からなかった**のが問題だった。
音声を聞き返しても、どこで落としたのか特定できない。

だから作るものは「問題を解かせるアプリ」ではなく、
**聞き取れなかった場所を自分で見つけられる道具**。

対象は当初、全商英検を受ける商業高校生。
のちに大学入学共通テストのリスニングにも広げる方向で検討中。

## 2. 揺らしてはいけない原則

### 権利のないものは配らない

「音声を配らない」ではない。**許諾を得ていないものを配らない**。

試験音源の著作権は主催者にある。許諾なくサーバーに置いて配信すると、
複製権と公衆送信権に触れる。だから許諾がない音源については、
**利用者が自分で入手したものを自分の端末で読み込む**形にして、
サイトは公式サイトへのリンクだけを案内する。

逆に言えば、**許諾を得た音源は配ってよい**。それが許諾を取る意味。

| 音源 | 許諾 | 扱い |
| --- | --- | --- |
| 全商英検 | なし | リンク案内のみ。利用者が自分で入手する |
| 共通テスト | 申請中 | 下りれば同梱して、ワンタップで読み込めるようにする |
| 利用者が持ち込む任意の音声 | 不要 | そのまま読み込める |

どの経路でも、**リスニング機能そのものは同じ**。
読み込み口が増えるだけで、処理のしくみは変わらない。
だから許諾が下りなくても、全商向けと汎用の道具として完成している。

過去にサーバー側で音声を処理する案も検討したが、
「利用者が操作しただけ」という理屈は通らない（まねきTV・ロクラクII最高裁判例）。
サーバー運営者が複製主体とみなされる。**処理はすべて端末内で行う**という判断は、
許諾の有無にかかわらず変えない。

### 断定しない

AIの文字起こしには必ず誤りがある。
誤った文字起こしを正解として見せると、**間違った文法解釈を学ばせてしまう**。
これがこの種の道具で一番避けるべき害。

→ 文字起こしは「答え」ではなく「音声への索引」として位置づける。
　 不確かな場所には印を立て、タップすれば実際の音で確かめられるようにする。

### 利用者のものを外に出さない

向きが大事。**受け取るのはよい。送り出すのがだめ。**

- **外に出さないもの** … 利用者が読み込んだ音声、録音した自分の声、
  文字起こしの結果、練習の記録。これらは一切サーバーへ送らない
- **受け取ってよいもの** … 音声認識モデル（約80MB）、
  許諾を得た教材データ。これは普通のウェブサイトと同じで、原則に反しない

つまり「端末の外に出さない」は**利用者の情報についての約束**であって、
サイトが何も配信しないという意味ではなかった。
共通テストのデータを同梱しても、この約束は破られない。

## 3. 検証で分かったこと

実際の試験音源（令和7年度第75回 全商英検1級・74回2級、計57分）で測定した。
測定に使ったスクリプトは `tools/` を参照。

### 精度

| 項目 | 結果 |
| --- | --- |
| 単語誤り率 | **4.1%（1級）／ 5.0%（2級）** |
| 処理速度 | 実時間比 **0.17×**（29分の音声を5分） |
| 意味が変わる誤り | 57分で **3箇所** |
| そのうち検出できた数 | **2箇所** |

### 誤りの種類別の検出率

| 種類 | 件数 | 検出率 |
| --- | --- | --- |
| 内容語（dresses → sandwiches など） | 21 | 48% |
| 人称（you'll → he'll など） | 11 | **18%** |
| 数量・時間 | 22 | 5% |
| 否定（can → can't など） | **0** | — |

**否定の誤りは57分で一度も起きなかった。** 一番危険だと想定していたが、
音が目立つうえ訓練データも多いので、Whisperが得意な領域だった。警戒対象から外してよい。

**固有名詞はよく捕まる。** Kyoko → koko、Tamotsu → tomozu、homeroom → room は全て検出できた。
知らない語は複数のモデルが別々の解釈をするので、不一致が確実に出る。

**人称だけが構造的な穴。** `you'll → he'll` は
「tell him that ___ write and call」という文脈で言語モデルが he'll を強く支持するため、
**モデルは自信を持って間違える**。確信度でも複数モデルの比較でも捕まえられない。

### 検出のしくみと、その限界

2つの信号のANDで判定した。

1. base と small の文字起こしが食い違う
2. base の語ごとの確信度が低い

適合率81%、再現率22%が上限。**5回に4回は見逃す。**

確信度だけで判定する方式も試したが、再現率78%まで上げると誤検出が144件出て
適合率24%まで落ちた。使い物にならない。

別系統のモデル（wav2vec2、内部言語モデルを持たないCTC）を相方にする実験もしたが、
`you'll → he'll` は検出できず、要確認が8語から138語に増えて適合率26%まで悪化した。
**独立しすぎた相方は、信号がノイズに埋もれる。**

→ 結論：**検出器で守りきるのは不可能**。
　 代わりに、危険な種類（人称の短縮形）を**規則で常に警戒対象にする**。
　 そして文をタップすれば即座に音に戻れることを、本当の防御線にする。

### 途中で気づいた測定ミス

一時は「誤り192語、再現率11%」という数字が出ていたが、
参照スクリプトの全行末に貼り付け由来の `[cite: 2]` が82箇所混入していた。
164語分が誤りとして数えられていた。**実際の誤りは30語弱だった。**

AIの性能が悪いと思ったら、評価データ側の汚れだった。
`tools/run_zensho.py` はこの種のマーカーを自動で除去するようにしてある。

## 4. 技術の選択と理由

### 音声認識モデル

**`onnx-community/whisper-base_timestamped` ひとつだけ。約80MB。**

- **なぜ base か** … tiny は英語が崩壊して使えない。small は精度が上だが250MBで
  実時間比0.4倍。**base と small の差は日本語の精度にしか出ず、日本語は不要**だった。
- **なぜ `_timestamped` 版か** … 語ごとの時刻には、モデル内部の注意機構の出力が要る。
  標準版はその情報を含めずに書き出されているため、語ごとの時刻を要求すると失敗する。
- **なぜ1つだけか** … 言語判定に標準版、本処理に `_timestamped` 版を使っていた時期があり、
  **中身が同じ重みなのに160MB受け取っていた**。同じモデルを使い回せば80MBで済む。
  語ごとの時刻が取れないときは、同じモデルのまま区間ごとに要求を落とす。

### 実行方法

**既定はWASM（CPU）。GPUは設定で選べるが既定は切。**

- iPhoneのSafariでWebGPUを使うとメモリ超過で画面ごと落ちる
- CPUで実時間比0.2倍前後が出ており、**速度は足りている**
- GPUを使う場合、符号化部分だけ32ビット、復号部分は4ビットに落とす
  （全体を32ビットで載せると落ちる）

**処理は別スレッドで行う。** 使えない環境では自動でメインスレッドに切り替え、
「終わるまで画面の操作ができません」と正直に表示する。

### 日本語の案内トラック

試験音源には日本語の進行案内が混ざる。これを英語として起こさせると、
**同じ語を延々と繰り返して終わらなくなる**ことがある。

→ 本処理の前に冒頭18秒だけ言語を指定せずに聞き、かな漢字が出たら案内トラックと判定して
　 本処理に入らない。すり抜けた場合の保険として、
　 同じ3語の並びが15%を超えたら暴走とみなして打ち切る。

**未解決** … 共通テストは全体が1本の音声で、日本語と英語が同じファイルに混在する。
今の判定はファイル単位（冒頭18秒）なので、**全体が案内トラック扱いになって英語部分が処理されない**。

無音での分割はできたので、残るのは**区間ごとに日本語かどうかを見る**ことだけ。
今は冒頭で一度だけ見て、以降は全区間を英語として処理している。

### 長い音声を区間に分ける

30分の音声だと、これまでは5分ほど何も出ないまま待たされていた。
**静かなところで区間に分け、終わった区間から順に画面へ出す**ようにした。

区切りの置き方は次のとおり。

- 目標は45秒。その前後12秒の中から、一番よい切れ目を探す
- 切れ目とは「160ミリ秒以上、静かなところ」。その真ん中で切る
- 見つからなければ、せめて一番音の小さいところで切る
- **90秒以下の音声は分けない。** 全商の音源は一問ずつ分かれていて元から短いので、
  これまでとまったく同じ動きになる

**なぜ時間で機械的に切らないか。** 語の途中で切ると、その語は両側で潰れる。
静かなところを選べば、切れ目はたいてい文の切れ目と重なる。
だから**文が区間をまたがない**ことになり、区間ごとにそのまま画面へ足していける。

**静かさの基準でつまずいた点。** 最初は「下位20%の大きさ」を基準にしていたが、
休止が短い音源（休止0.25秒・発話2.5秒で試した）だと下位20%にも声が入る。
すると基準が声の高さまで上がって**どこも静かということになり、声の真ん中で切っていた**。
下位5%に下げたうえで、**真ん中の高さ（＝おおむね声）の4分の1**を上限として被せて直した。
これで、休止がほとんど無い音源でも声の上には切れ目を置かなくなった。

29分の音声で40区間、区切りの計算は27ミリ秒。

区間ごとに分けたことで、副産物が3つ出た。

1. **粗い時刻へのフォールバックが区間単位になった。** これまでは語ごとの時刻が
   一箇所でも取れないと、全体を粗い時刻でやり直していた。今はその区間だけ落とす。
   どの語がおおよそなのかも語ごとに覚えるので、付箋の判定も正確になった
2. **暴走の打ち切りも区間単位。** 巻き添えが1区間で済む
3. **中止と再開ができる。** 途中で止めても、そこまでは残る。
   次に開くと「続きから起こす」で再開する

### 表示の単位

**文ごと。** 語ごとのタップも実装したが外した。

- 聞き直したい単位は語ではなく文
- 文単位にすると、区間リピート・文送り・文ごとの練習が**すべて同じ操作に収まる**
- 語だけタップできると「なぜこの語だけ？」という疑問が生まれる

付箋（不確かな語の印）は**表示のみ**。タップ対象にはしない。

## 5. 著作権の整理

### 全商英語検定（全国商業高等学校協会）

- 音源の配信は**しない**。利用者が公式サイトから入手する
- 公式サイトへのリンクは適法（リンクは複製でも公衆送信でもない）
- 直リンクではなく過去問ページへのリンクにする。iframeで埋め込まない
- 公開されたリンクポリシーは見当たらなかった

### 大学入学共通テスト（大学入試センター）

- 試験問題の著作権はセンターに帰属（第三者著作権部分を除く）
- **二次利用**（複写、他者への配布、問題の一部または全部を使った問題集の作成。
  インターネット上を含む）には、**利用前に「試験問題利用申請」が必要**
- 手続きは電話（総合案内 03-3468-3311）から。許諾の可否は通常8営業日以内
- 利用開始日は試験実施日の翌日以降
- 利用後、成果物を提出（ウェブサイトなら使用状況が確認できるURL）
- 第三者が権利を持つ部分は、**利用者の責任で別途許諾を得る**
- リスニング音声はmp3で公式に公開されている
- リンクは原則自由。許可不要。ただしリンク先がセンターのサイトであることを明記し、
  自サイトの一部に見える形にしない

**利用許諾を取得済み（2026年7月29日申請 → 許諾）。** 興國高校・橋口の名義。
これにより、共通テストの音声・問題冊子・台本を**同梱して公開してよくなった**。

許諾にともなう義務（守ること）：

- **出典を明示する。** 「令和8年度 大学入学共通テスト 英語／独立行政法人 大学入試センター」。
  トップページの脚注、一問一答の各画面、冊子ビューア、台本の欄に入れてある
- **改変したと分かる注意書きを付ける。** 設問ごとの分割・出題順の変更・音声の区切り・
  日本語案内の要約表示などは編集にあたる。「試験問題そのものではない」と各所に明記
- **第三者が権利を持つ部分は、利用者（橋口）の責任で別途許諾を得る**
- **成果物の提出。** ウェブサイトなので、公開後に**使用状況が確認できるURLをセンターへ連絡**すれば足りる
  （データの送付は不要）。許諾連絡のメールは保管しておく
- 申請した利用目的以外に使うときは、別途申請が必要

`.gitignore` の「試験問題データを弾く」段落は外し、`practice/data/`・`listening/scripts/`・
`catalog.json`・`exams.json` を公開対象にした。手元の私物音声を誤って上げないための `*.mp3` は残し、
使う1本（`r8-listening.mp3`）だけを明示的に通している。

## 7. 判断に迷ったときの拠り所

**迷ったら、利用者が音に戻れるかどうかで決める。**

このサイトの価値は、正解を教えることではなく、
**自分の耳で確かめる場所まで一瞬でたどり着けること**にある。
AIの判定を増やす方向ではなく、確かめやすくする方向に倒す。
